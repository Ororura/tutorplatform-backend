# Веб-упражнения HTML / CSS / JavaScript

## Использование

1. В банке заданий нажмите **Создать задание**.
2. Выберите предмет **Веб-разработка**, тип **Код**, язык **HTML / CSS / JavaScript**.
3. Выберите один из 15 шаблонов, при необходимости измените условие и стартовые файлы.
4. Укажите доступные ученику файлы и режим проверки:
   - **Автоматическая**: серверные проверки определяют итог попытки.
   - **Преподавателем**: код сохраняется без запуска тестов, попытка ожидает решения преподавателя.
   - **Смешанная**: результаты автотестов сохраняются, окончательное решение принимает преподаватель. Инфраструктурный сбой остаётся ошибкой проверки.
5. Сохраните задание, активируйте его и прикрепите к теме либо выдайте в домашнем задании.

Ученик редактирует разрешённые файлы, обновляет предпросмотр, выбирает ширину 375/600/1024 px,
смотрит сообщения консоли, пользуется подсказкой и запускает серверную проверку. **Проверить** не
создаёт попытку; **Отправить решение** сохраняет неизменяемую версию файлов. Черновики хранятся
локально с отдельным ключом для аккаунта, задания и контекста. При запрете локального хранилища
ученик получает сообщение о невозможности сохранения.

Преподаватель открывает код и предпросмотр в домашнем задании либо в блоке **Решения на проверку**
профиля ученика; второй вариант включает самостоятельную практику по темам. Можно принять
решение или вернуть его с комментарием до 4000 символов. Ученик видит комментарий в задании.
Автотесты и решение преподавателя отображаются отдельно; завершение домашнего задания происходит
после принятия решения существующим механизмом прогресса.

## Каталог

HTML: заметка, изображение, форма, навигация.
CSS: карточка, Flexbox, Grid, состояния кнопки, адаптивность.
JavaScript: стоимость покупки, скидка, фильтрация чётных чисел.
DOM: счётчик, валидация формы, список дел с ручной оценкой оформления.

Шаблоны и 29 критериев находятся в frontend `src/entities/task/model/web-exercise-templates.json`.
Эталонные решения находятся только в тестовых fixtures и не импортируются приложением.

## Запуск и развёртывание

Flyway V017 добавляет комментарии к попыткам, статус `SKIPPED` и системный предмет «Веб-разработка».
Старые задания Python/Java сохраняют существующее поведение. Веб-задания используют `CODE` с
окружением `WEB`; отдельный тип задания и новая система прогресса не создаются.

Перед использованием автопроверки подготовьте образ на Docker daemon, используемом worker:

```sh
cd execution-worker
docker build -f Dockerfile.runtime-web -t tutor-web-runtime:1 .
```

Локальные `compose.yml` и `compose.local.yml` собирают образ автоматически. Для другого имени
задайте `EXECUTION_RUNTIME_WEB_IMAGE` у worker. Для production подготовьте неизменяемую ссылку
на этот образ и обновите backend, frontend и worker вместе. Автоматическое развёртывание в этом
изменении не выполняется.

Серверная проверка использует существующие авторизацию, CSRF, ограничения частоты и размера
исходников. Сервер сверяет закрытые файлы с конфигурацией преподавателя; клиент не выбирает
окружение, тесты, статус или режим проверки. Node запускает только сценарии преподавателя;
ученический JavaScript выполняется в Chromium. Каждый критерий получает новый Docker-контейнер
без сети, с read-only корнем и workspace, непривилегированным пользователем, снятыми capabilities,
лимитами CPU, памяти, процессов, времени и вывода. Для Chromium предусмотрены отдельные минимумы
PID/tmpfs/дескрипторов. Граница серверной изоляции — контейнер; browser context сам по себе
не считается защитной границей. Таймауты и ошибки запуска среды не засчитываются как успешные
проверки.

Предпросмотр использует отдельный документ `/web-preview` с `sandbox allow-scripts`, непрозрачным
origin и собственной CSP: нет доступа к DOM/cookies/localStorage платформы, внешним ресурсам,
формам, вложенным фреймам и сети. Политика скриптов основного приложения остаётся строгой.
Сообщения предпросмотра используются только для консоли, не для оценки. Бесконечный цикл в локальном
предпросмотре может потребовать перезагрузки вкладки; лимит времени применяется на сервере.

Это небольшие упражнения без npm, сборщиков, импорта внешних зависимостей или внешнего API.
Файлы CSS и JavaScript подключаются тренажёром автоматически. Черновик не синхронизируется между
устройствами; отправленные попытки сохраняются на сервере.

## Проверки

```sh
# frontend: после подготовки образа
npm run test:web-exercises
npm test
npm run typecheck
npm run lint
npm run build
PLAYWRIGHT_BASE_URL=http://127.0.0.1:3301 npm exec -- playwright test e2e/web-exercises.spec.ts

# worker
./gradlew test
./gradlew sandboxIntegrationTest --tests '*DockerSandboxRuntimeIntegrationTest.web*' --tests '*DockerSandboxRuntimeIntegrationTest.infiniteWeb*'

# backend
./gradlew test --tests '*WebExercise*Test' --tests '*CodeSubmissionApiIntegrationTest' --tests '*SubmissionApiIntegrationTest'
```

Каталожный тест запускает все эталонные решения и проверяет, что каждый стартовый вариант
проваливает хотя бы один критерий. Браузерные тесты используют реальную production-сборку с
подменой API; серверные интеграционные тесты отдельно проверяют PostgreSQL, права доступа,
режимы проверки, сохранность исходников, комментарии и завершение домашнего задания.
